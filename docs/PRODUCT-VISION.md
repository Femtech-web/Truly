# Truly product vision

Truly helps people learn by practising in the real application: share a screen deliberately, receive contextual explanation or one guided action, attempt a challenge, and retain verified progress.

The Nimiq Pay Mini App is the place to start a personal Task, discover creator Paths, authorize the wallet and follow progress. The macOS companion handles screen-aware learning and pointer guidance. Truly Core owns durable identity, sessions, reviewed Path versions, entitlements and evaluation. The website explains the product and distributes the companion.

The first release targets Nimiq starter Paths, NIM and USDT Path purchases, and reviewed Creator Studio publishing. Creators can teach programming, Web3, video editing, design, general knowledge or other subjects through supported evidence modes/environments, with multiple tags and a public Path library. A learner may also describe an immediate goal such as “learn Zama privacy”; Truly turns that into a private Task rather than requiring marketplace content first.

Long term, Truly may expand to a broader marketplace, more platforms, paid human tutors, teams, certificates, opt-in reminders, rewards, staking education and additional currencies. These are roadmap possibilities, not shipped capabilities or guaranteed earnings. Each must preserve consent, non-custodial wallet authority, content rights and verified learning.

## Companion interaction direction — planned, not shipped

An optional follow-pointer mode should let the teal companion stay near the learner's system cursor without dragging. Keep a stationary mode, hide/pause controls, a keyboard invocation and accessible alternatives. Never replace the system cursor, obstruct ordinary clicks or confuse pointer movement with consent to capture.

Push-to-talk should be another explicit way to ask a question: show listening, deliberately capture the chosen display when the request is submitted, show a restrained thinking state, then return a text answer beside the companion. Spoken playback is optional. No always-on microphone or continuous screenshots. Before a cloud request, obtain processor-specific consent and disclose what leaves the Mac.

The model uses the shared frame, question and active Task context to infer the relevant area; it cannot guarantee what a vague question refers to. Ask for clarification when uncertain, and validate every suggested target against the captured display. The current build supports draggable click-to-capture and text input only; following and voice remain future runtime work.

Retention should come from useful feedback, owned Paths and resumable Tasks. Initial planned revenue is first-party Path sales and direct creator purchases; marketplace fees or subscriptions require an implemented and tested settlement/support model.
