# Product model

Truly turns learning from a content session into resumable work. Its retention and commercial model both follow the same rule: value is created when a learner can continue doing something useful.

## Retention

### A Task keeps the learner’s place

Every personal goal or creator Path becomes a wallet-owned Task. It stores the approved plan, current step, completed results and relevant resources. Returning to Truly resumes the first unfinished step instead of asking the learner to rebuild context.

### Phone and Mac form one workflow

The Mini App is the library and control surface: discover Paths, manage wallet access, choose a Mac and review progress. The native companion handles the moment of doing: understand the visible screen, ask by text or voice, try the action and check the result.

This division gives each surface a clear reason to return without duplicating the same interface on both devices.

### Progress comes from practice

Passive reading does not mark a step complete. When a Path defines visible practice criteria, the learner deliberately chooses **Check my work** and receives an AI-checked result. Saved progress therefore represents attempted work rather than time spent in a feed.

### Wallet ownership creates a durable library

Private Tasks, free Paths, purchased Paths and progress belong to the connected wallet owner. A creator update produces a new approved version; it does not rewrite the version already attached to a learner. This makes returning safe and predictable.

### Creator quality supports repeat use

Creators can organize knowledge into ordered, reviewable Paths instead of isolated posts or links. Clear outcomes, requirements, resources and completion criteria make a useful Path discoverable again and give learners a reason to explore more work from the same creator.

## Revenue

Truly earns around learning products rather than attention or wallet custody.

### Open entry

Learners can create private Tasks and start free Paths without purchasing content. This lets the product prove its screen-aware learning loop before asking for payment.

### First-party Paths

Truly Studio can publish premium Paths and receive their NIM payments through its verified creator wallet. These Paths provide direct product revenue while using the same review, versioning and payment rules as every other creator.

### Creator-owned sales

An independent creator can publish for free or set a NIM price. Paid access shows the exact Path version, amount, network, creator and recipient before native Nimiq Pay approval. Core independently verifies settlement before granting one durable entitlement to the buyer.

The creator recipient is a verified wallet identity rather than a payout address typed into a form. Truly never controls the creator’s private keys or the learner’s funds.

### Current commercial boundary

The implemented model supports first-party Path revenue and direct creator sales on Nimiq Mainnet. It does not represent an automatic marketplace commission, subscription or advertising model. USDT, automatic revenue splitting and custodial creator balances are not part of this payment path.

## Why the model fits Nimiq

Nimiq connects identity, payment and continuity in one understandable flow:

1. the wallet proves who owns the Task or Path;
2. the creator wallet establishes the payment recipient;
3. Nimiq Pay shows and approves the native transaction;
4. Truly Core verifies the public settlement independently; and
5. the resulting access remains attached to the buyer’s wallet.

The commercial layer therefore strengthens the learning product instead of behaving like a separate checkout integration.
